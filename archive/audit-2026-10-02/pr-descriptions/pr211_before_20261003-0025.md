TITLE: Audit fixes: govern cache followers, close redaction and guardrail gaps, correct the docs

## What this is

A full audit of the repository and the shared deployment, done before Sprint 4 feature work, and the fixes it produced. The complete record, with method, evidence and what was *not* tested, is [`docs/audit_2026-10-02.md`](docs/audit_2026-10-02.md). Deployment hardening (compose, Dockerfile, deploy workflow) is deliberately **not** in this PR; it is a separate branch because merging it restarts the datastore containers.

## The finding that matters most

**#210 removed the governance from semantic-cache followers.** A follower joining an already-resolved cluster had the leader's resolution written as `complete` with no eligibility check, no input screening and no risk assessment. Reproduced on the shared system with the deployed `main`: a priority-1 follower (INC0010243) finished `complete` in 3.1 s, `human_review_required=false`, resolution written, no approval row, while an independent priority-1 incident correctly parked. This breaks the PRD's "no high-risk action without a recorded approval" (NFR-05, FR-13, FR-17).

**Fix:** `follower_reuse_verdict` runs the deterministic gates (`check_eligibility`, pattern screening, `assess_risk` on the follower's own record). A clean, low-risk follower is still resolved with zero LLM calls, as #210 intended. Anything else runs the full governed graph, still given the cached draft so only `generate` is saved. A failed ServiceNow write in that path now fails the execution instead of being logged and reported as success.

## Verification

- `ruff check`, `ruff format --check`, `mypy src`, `export_openapi.py --check`, `scan_repo_secrets.py`: clean.
- **1,941 unit tests pass** (1,549 at the start), under several random orders (`pytest-randomly`).
- New regression tests per fix; the follower fix is proved by `tests/test_follower_reuse_governance.py` (5 of 6 risky followers were applied directly before the fix).
- `pip-audit`: no known vulnerabilities. `bandit`: nothing on the changed code.
- **Live, on the shared deployment (before these fixes):** 11 labelled `[AUDIT-2026-10-02]` incidents run end to end, reproducing F-1, the redaction leak and the locked-ticket classifier call; parked and blocked paths verified to write nothing.

## What is NOT verified, and what reviewers should know

- **The fixes themselves are not live-verified.** They are covered by tests with fakes. After this is merged and deployed, re-run the priority-1 follower and secret-in-JSON scenarios on the shared system.
- The PostgreSQL-backed and integration suites were not run locally (they need Docker); this PR's CI is their first run on these changes.
- No live approve/reject was run (no current operator secret), so the knowledge-capture loop is not live-tested.
- The semantic classifier's detection rate is unmeasured; the red-team figures are the deterministic layer only.
- **Behaviour changes to weigh in review:** ambiguous patterns now cost a classifier call instead of an instant block; followers that fail the gate lose the zero-LLM saving (they still reuse the draft); an unfaithful composed article is no longer published; ineligible incidents skip all model layers.
- Not fixed here, documented in the audit: the semantic-cache threshold is calibrated in-sample (F-3); three direct ServiceNow callers bypass `ToolRegistry` (F-15); the risk policy's service tiers name services the shared instance does not have (F-17); the worker was OOM-killed under a six-incident burst (O-8).

## Deployment

Merging triggers the normal deploy to the shared EC2. No migrations, no new environment variables required, no compose change. `openapi.json` is regenerated (bounded `reason`/`evidence`, config flag description).
